## 规则

文件表交付必须说明对象存储位置、文件定位方式、访问 URL 如何生成，以及外部访问如何鉴权。不要把页面能自行拼下载路径视为后端文件访问契约已经完整。

用户明确临时公开语义：有效期内任意持有链接的人可访问，当前不做接收人身份或未知访问者校验。临时授权优先复用 `storage/ephemeral` 的 TTL，不因临时访问本身新增持久化授权表；文件元数据仍由数据库保存。是否需要额外的权限变化联动等行为，不从这项授权自行扩展。

用户提出 `url` 持久化站内相对访问路径，例如 `/xxx/file.md`，浏览器按当前域名解析；不持久化域名。后端负责生成路径，表格直接使用该路径。表格增加生成临时访问链接按钮，弹窗返回可复制链接；临时令牌和期限不覆盖记录的稳定路径。

## 原因

用户在文件模板交付后指出最终访问链接没有生成，并要求对照本地 NocoBase 研究外部文件访问权限。

用户随后纠正接收人校验和数据库持久化建议：临时公开无需验证接收人，临时状态应优先使用项目已有 ephemeral 能力。

用户进一步纠正 URL 无需落库的建议：持久化相对路径可以保留稳定入口且不绑定部署域名，临时公开通过独立按钮和弹窗完成。

## 适用场景

文件表模板、文件响应、外部消费和权限设计。公开访问和临时授权的具体新方案仍须按本轮用户决策确定，此反馈不授权所有文件公开。
