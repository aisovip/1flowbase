# 主会话统一归档，子代理仅在轨迹中查看

## 规则

- 一个主会话是一个归档单位，subagent属于该会话；保留来源标识和父子执行关系。
- 二级会话历史只读取主对话：系统提示词、用户输入、AI最终回复；默认最近五轮并可滚动向前读取。
- 三级直接展示整个主会话的统一时间线，主 Agent 与任意层级子代理的原始事件按时间分页；不以主任务、子代理或 request_id 创建外层折叠容器。
- Subagent 是来源筛选，原始事件类别及生产者身份继续保留；查询、分页、筛选由后端在 canonical 主会话范围内完成。
- 从某轮 AI 回复打开只定位到该轮时间，不将查询范围缩小为该轮或子树；仍能读取更早和更晚事件。
- 不通过在二级主对话追加可折叠子代理卡片来冒充会话聚合；后端会话归属、UI与AI读取契约须一致。

- 会话归属与折叠层级修复必须保留原有轨迹界面的时间泳道、分类栏、紧凑事件行、搜索和详情侧栏；不得顺带替换为新的表单式布局。优先复用已有展示组件，只调整所需的数据接入和层级。

- 事件分页沿用 Agent Flow 的逐页自动加载，直到全部事件读完；不要求手动点击加载更早/更新事件。行尾主代理不加标记，子代理只显示 `subagent`，完整来源身份仍可查看。

## 原因

用户否定了把父子关联转换为二级子代理对话卡片的方案。二级用于理解人与主代理的交互，三级用于查看主会话内所有执行过程，并可定位产生某轮回复的时间。用户进一步否定将主任务和子代理作为折叠节点，要求一个主会话时间线及来源筛选。两种语义混合会破坏统一日志查询与阅读路径。用户随后指出原有 UI 正常，否定为统一会话查询而全面替换样式；数据归属修复不构成界面重设计授权。

## 适用场景

Codex、Claude Code、DeepSeek Harness、OpenCode等采集记录归档，以及主流程和子代理日志的展示、查询与MCP接口。
